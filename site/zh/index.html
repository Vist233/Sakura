构建专用的 Coding Agent，不必重写每个 Agent 都需要的部分。模型、会话、工具、执行环境和策略，都可以替换或组合。

import { createAgent } from "sakura-agent";

// read、write、edit、bash、会话、压缩、目标：都已具备
const agent = await createAgent({ model });
const result = await agent.run("Fix the failing tests.").result;

为什么是 Sakura

Coding Agent 正在进入软件内部。

它不只是人打开来用的工具，也是另一个程序里运行的一部分。

  1. 并行探索多个 Agent 同时尝试不同的方案。
  2. 独立审查工作中的 Agent 派生一个只读的 Reviewer。
  3. 本地与远程同一个 Agent 在本机或另一台机器上工作。

问题不在模型够不够聪明。

而在于你的软件怎样组织和控制 Agent。要得到一个 Agent，有三条路。

采用现成的 Agent 产品

上手快。

你的软件要适应它的交互、工具、状态和生命周期。

从模型 API 自建

完全可控。

Agent Loop、工具协议、上下文、会话、错误处理和恢复，都要自己重写。

复用，但不耦合。

  
子 Agent 自动带上父 Agent 的审查和脱敏，插件之间不需要互相导入。

  

    
父 Agent
      reviewredactionagentscontexttoolslimits
    

    
→

    
子 Agent
      reviewredaction自己的 context、tools、limits
    

  

  
这是装配层在运行时的组合，不是源码导入。传给子 Agent 的插件，可以用 subAgents.notInherited 调整。






  
Branch Reviewer：Infinity 的做法。

  
工作中的 Agent 派生一个 Reviewer：它保留完整的历史，但只能读。Reviewer 把建议交回来，由主 Agent 决定是否采纳。

  
  
调度、结构化结果、建议交付和 Reviewer 的生命周期，是 Infinity 的代码；Sakura 提供会话 fork、装配、插件和执行边界。Reviewer 的模型还能看到某个工具，不代表它能运行这个工具：每次调用运行之前，都由 Guard 检查。
