# Framework gaps found while building Sakura Terminal

The terminal uses the framework through `sdk/index.ts` only and does not patch it. Each entry says what was missing or surprising, how the terminal works around it (inside `terminal/`), and the change proposed for the framework. Evidence is in the code references; nothing here was changed outside `terminal/`. Ids start with `T` so they do not clash with `G1` to `G9` of `docs/30-agent-surface-audit.md`.

| Id | Gap | Workaround in the terminal | Proposed framework change | Priority |
|---|---|---|---|---|
| T1 | **Reasoning text is not an event.** The chat client yields `reasoning_delta`, but the kernel only keeps it as a `provider` part of the finished message (`loop.ts` handles `text_delta` and `provider` only). A UI cannot show "thinking" while the model reasons. | The live area shows "Working (Ns)" instead. | Emit a `message_update` with a reasoning content kind (or a `reasoning` event), kept out of the log. | Medium |
| T2 | **Steered and queued messages emit no event.** `steer` and `queue` text is appended to the log (`appendMessage`) when taken, with no `message_end`. A UI cannot tell when the agent took the message. | `run-driver.ts` reads `agent.log.branch()` on `turn_start` and `run_end` and matches new user messages against what it sent. | Emit `message_end` for such a user message when it is appended. | Medium |
| T3 | **`message_start` comes after the stream.** For an assistant message the order is `message_update`\* then `message_start`, `message_end` (the message is complete before `message_start` is emitted). | `transcript.ts` treats deltas as belonging to the current reply and does not depend on `message_start`. | Emit `message_start` before the first delta. | Low |
| T4 | **A refused call has no `tool_start`, and the review event does not name the call.** The review plugin emits `{kind:"review", tool, outcome, decidedBy, reason}` keyed by tool name; the loop then answers the call with `tool_end` (error "Not allowed: ...") without `tool_start`. With parallel calls to the same tool the match by name can pair the wrong decision. | `transcript.ts` keeps the last review note per tool name and attaches it to the next block of that name. | Add `callId` to the review event; or emit `tool_start`/`tool_end` with a `denied` marker. | Medium |
| T5 | **The hard rules cannot be told not to look at the directory.** `reviewPlugin` always receives `cwd` (`HookContext.env.cwd`), and a read-only command with a path argument that may leave the directory (`ls /etc`) is passed on to the reviewer model instead of being allowed by the hard rules (`hard-rules.ts`, `mayLeaveDirectory`). The product requirement is "no outside-directory rule". | `permissions.ts` replaces the default reviewer policy (`REVIEW_POLICY`) so that the reviewer treats the whole machine as the agent's workplace; the cost is one reviewer request for such calls. | A review option such as `trustedRoots: ["/"]` or `directoryRules: false` so these calls are allowed by the hard rules. | Medium |
| T6 | **Types not exported.** `McpServerConfig` and `McpServerStatus` are not in `sdk/index.ts`. | Derived with `AgentConfig["mcp"]` and `Agent["mcp"]`. | Export both types. | Low |
| T7 | **The scripted model is not exported.** `createFauxClient` lives in `@sakura/testing`, which the SDK does not export. A host that wants deterministic tests of its own UI has to write one. | `src/faux-client.ts` is a 60-line scripted `LlmClient` written against `LlmClient` only; the binary can use it through `SAKURA_TERMINAL_FAUX_SCRIPT` for the pseudo-terminal test. | Export `createFauxClient` from the SDK as a testing helper (separate entry point). | Low |
| T8 | **A cancelled request stays in the context without an answer, and models carry on with it.** Observed live with both providers: after Esc on "write a 3000 word essay", the next message ("which file did I ask for?") was answered together with the essay. | `session-controller.ts` puts `CANCEL_NOTE` before the next prompt after a cancel, and also on resume when the last message of the session is an unanswered user message; the view strips the note. | When a run is cancelled, append a marker (an assistant message "[interrupted by the user]") so the history is complete. | Medium |
| T9 | **Image input needs `compat.images`, which the presets do not set.** `compatPresets.deepseek` has no `images`, so the chat client replaces an image with the text "[an image was attached but this model cannot read images]" even though both DeepSeek and OpenCode Go read images (checked live, see the test report). | `providers.ts` adds `images: true` to the compat of both built-in providers (config key `images = true` for others); `--image`, `@image.png` and a pasted image path attach the file. | Set `images: true` in the framework's `deepseek` preset, or document that a host must. | Low |
| T10 | **The process did not exit after a cancelled request in a pseudo-terminal.** In the first live runs the process was still alive 5 s after `close()` returned, after Esc had cancelled a streaming request. The cause was not isolated (an open socket of the cancelled fetch or a paused TTY handle are the candidates). | `bin/sakura-terminal.mjs` calls `process.exit` after flushing stdout. | Find the handle that stays open (ask Node with `process.getActiveResourcesInfo()` after `agent.close()`). | Low |
| T11 | **Wake-up is not wired in the terminal.** `AgentConfig.wake` can start a run when a background command ends, but needs a host to show the run (`onRun`). | Not done: a command that the model moves to the background is reported to the model at its next turn only. | None (a terminal task), listed so it is not forgotten. | - |
| T12 | **Sub-agents are not configured.** `AgentConfig.subAgents` works but the terminal offers no definitions. | Not done. | None. | - |

## Where the framework worked as documented

`createAgent`, `run`, `queue`, `steer`, `cancel`, `rewindTo`, `fork`, `context()`, `usage()`, `goal()/setGoal()/clearGoal()`, `run(undefined, {compact: true})`, `reviewPlugin` with `breaker`, `redactionPlugin` with `wrap`, `compose` ordering, `AgentConfig.rules` and `corePlugins()` were used without changes and behaved as described in `docs/30-agent-surface-audit.md`. The session file lock, the resume of a session on a different provider, and the OpenCode Go session header (`x-opencode-session`) worked on the first try.
